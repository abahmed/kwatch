{{- if eq (include "kwatch.watchSecrets" .) "true" }}

WARNING: watch.secrets=true (the default). kwatch's ServiceAccount can read
every Secret in the cluster{{ if eq (.Values.rbac.mode | default "least-privilege") "full" }}, and rbac.mode=full grants list and watch on every resource kind{{ end }}.
kwatch keeps only hashes of Secret data, never the values. To remove all
Secret access set watch.secrets=false (--set watch.secrets=false); checks
that need Secrets then report that they cannot verify. rbac.mode=least-privilege
alone narrows other kinds but still lists Secrets.
{{- end }}
{{- $rbacMode := .Values.rbac.mode | default "least-privilege" }}
{{- $secretsOn := eq (include "kwatch.watchSecrets" .) "true" }}
{{- if or (ne $rbacMode "full") (not $secretsOn) }}

NOTE: kwatch has read access to the built-in kinds it understands only. Custom
resources (cert-manager, Argo CD, operators and any other CRD) are not watched,
so failures in them are not reported, and /health lists them under coverage as
permission_denied. To watch custom resources and kinds added later, set
rbac.mode=full.
{{- if and (eq $rbacMode "full") (not $secretsOn) }}
rbac.mode=full is not in effect here: watch.secrets=false renders the same
explicit list as rbac.mode=least-privilege, because RBAC cannot remove Secrets
from a wildcard grant. Keep Secrets watched to use rbac.mode=full.
{{- end }}
{{- end }}

{{- if .Values.persistence.emptyDir }}

WARNING: persistence.emptyDir=true. Kwatch state (open incidents, baselines,
thread IDs) is stored on an emptyDir volume (limit
{{ .Values.persistence.emptyDirSizeLimit | default "2Gi" }}) and is lost when the pod is rescheduled or
restarted on another node. Incidents may be announced again after a restart.
Use a PersistentVolumeClaim for production.
{{- end }}
